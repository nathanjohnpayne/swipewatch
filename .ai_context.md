# AI Context — Swipe Watch

## Project Name
Swipe Watch

## Project Type
Static web app (no build step, no framework, no server)

## Primary Languages
- JavaScript (Vanilla ES6+)
- HTML5
- CSS3

## Key Entry Points

| File | Purpose |
|------|---------|
| `public/index.html` | Full app shell — HTML structure, onboarding overlay, card container |
| `public/app.js` | All application logic — content pool, swipe mechanics, session management, coin bank, analytics |
| `public/styles.css` | All styling — animations, responsive breakpoints, card layouts |
| `public/gtag-init.js` | Google Analytics bootstrap (external file so the CSP can forbid inline script) |
| `firebase.json` | Firebase Hosting config — `public/` as the hosting root, security headers (CSP etc.), cache headers, SPA rewrite |
| `AGENTS.md` | AI agent instructions and behavioral rules |

## Directories With Non-Obvious Purpose

| Directory | Purpose |
|-----------|---------|
| `public/` | Firebase Hosting root — the only directory that is deployed. Holds the site assets and nothing else; repo tooling, tests, docs, and local agent config must stay outside it so they are never served |
| `rules/` | Repository-level invariants enforced on all agents and contributors |
| `plans/` | Execution and rollout plans for features or migrations |
| `specs/` | Intended behavior definitions (acceptance criteria, feature specs) |
| `tests/` | Vitest app/hosting tests plus hub-propagated shell tests (see below) |
| `functions/` | Placeholder — no serverless functions currently exist (see below) |
| `docs/` | Extended documentation beyond README/AGENTS.md |
| `scripts/ci/` | CI enforcement checks validating compliance with the AI Agent Tooling Standard |

## Directories Intentionally Absent

| Directory | Justification |
|-----------|--------------|
| `dist/` | No build step exists. Static files are deployed directly from source. If a build step is introduced, create this directory and update `.gitignore`. |
| `src/` | The site source files (`index.html`, `app.js`, `styles.css`, assets) live in `public/`, which is both the source and the deployed hosting root (there is no build step). |

## Standard Compliance Notes

- **`dist/` absent:** Intentional. Static site with no build output. Documented above.
- **`src/` absent:** Intentional. Site source lives in `public/`. Documented above.
- **`public/` present:** Declared in `.repo-template.yml` `extra_top_level_dirs`. It is the Firebase Hosting root so that only site assets are deployed. See `plans/hosting-public-dir.md`.
- **`tests/`:** Vitest suites (`tests/*.test.js`, jsdom) load the real `public/index.html` and `public/app.js`; `tests/hosting-config.test.js` guards the hosting root and security headers. The `tests/test_*.sh` files are hub-propagated review-tooling tests.
- **`functions/` empty:** No serverless or cloud functions. Exists as a placeholder. Add if backend functions are introduced.
- **`scripts/ci/` wired to CI:** CI enforcement scripts run automatically on push/PR via `.github/workflows/repo_lint.yml`. They can also be run locally before commits.
- **`.cursor/rules/deploy.mdc`:** A Cursor `.mdc` rules file providing deploy context to the Cursor agent. This is valid Cursor configuration (not a plain `.md` instruction file). Content mirrors `DEPLOYMENT.md`.

## Related Repositories
